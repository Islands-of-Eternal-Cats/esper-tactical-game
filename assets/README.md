# Ассеты

Два кита: `character-kit.glb` (кот) из `build-character-kit.py` и
`env-kit.glb` (окружение) из `build-env-kit.py`; `npm run assets` собирает оба.

Эталон один: `rusty.blend`. Все новые части — голова другого кота, снаряжение,
предмет в лапе — создаются **копией из него**, не с нуля и не импортом со
стороны. Одна съехавшая bind-поза ломает всех котов сразу, а обнаруживается это
обычно после того, как сделано двенадцать голов.

Правило процедурное, поэтому эталон здесь строится скриптом:

```
blender --background --python assets/build-character-kit.py
```

или `npm run assets`. Скрипт пишет `rusty.blend` и `public/models/character-kit.glb`.
Контракт готового кита проверяется автотестом `tests/character-kit.test.ts`:
имена мешей, сокеты, кости Mixamo, бюджеты треугольников и размера.

## Геометрия: из мокапов

Корпус и голова — меш, сгенерированный по трём ракурсам из `mocks/`:
`gen/tripo/` — OBJ с развёрткой и карта цвета 512² от Tripo (исходник
`mocks/tripo-anthropomorphic-cat/`). Это лучше первого пути через Hunyuan3D +
ремеш + свой проектор цвета: чистая топология, текстура без призраков ракурсов,
один хвост. Workflow Hunyuan (`gen/rusty_mv.workflow.json`) оставлен как
запасной.

Скрипт делает из него кит:

- **скелет по ориентирам** (`L`): пропорции сгенерированного кота — не
  пропорции болванки, и скелет подгоняется под меш, а не наоборот;
- **нарезка** по `HEAD_SPLIT_Z` на `head_rusty` и `body_stocky`;
- **разметка по частям** `gen/tripo/parts.json` — сегментация того же меша
  (AssetHub → Tripo part_segmentation, «balanced»): 21 часть, ровно наши 5409
  граней, сопоставлены по центроидам. По ней голова отделяется по шву (капюшон
  остаётся на корпусе), хвост — часть 9, а не «рыжее в радиусе»;
- **тепловые автовеса** Blender, сокеты помечены `use_deform=False`; поверх —
  три правила: хвостовые кости тянут только хвост (`confine_tail`), жёсткие
  детали — подсумки, бирка — целиком на одной кости (`pin_rigid_parts`; шов с
  одеждой оставляет веса диффузии), вершина без весов — ближайшей кости
  (`fill_orphans`). Вершина без весов остаётся в bind-позе и висит в воздухе —
  так «летал» кусок хвоста; тест кита это ловит;
- **цвет вершин из карты** — запасной, если картинка не доедет.

Rest-поза рук — A-поза мокапа. Клипы опускают руки постоянным приведением
`ARM_ADDUCT`, поверх которого идёт поза.

## Клипы

Пять клипов, по одному на занятие кота (`CatView['action']`), запекаются тем же
скриптом и лежат в GLB. Позы ставятся ключами — контакт и пронос у шага, взмах у
работы, — а не синусом: синус давал ровный поплавок без опоры на землю, и
коэффициентами это не лечится.

- Повороты в скрипте задаются вокруг **мировых** осей и переводятся в базис
  кости. Думать в осях кости, которая смотрит вниз и с произвольным roll,
  нельзя: ошибка знака там неотличима от ошибки позы.
- Кость `mixamorig:Head` клипы не трогают намеренно: рысканье головы — это
  внимание кота, им управляет рендер, и трек затирал бы взгляд каждый кадр.
  Проверяется автотестом.
- Root motion нет: позицию кота в мире ведёт симуляция. Подъём таза — смещение
  кости `Hips`, а не всей фигуры.
- Ключуются только затронутые кости — иначе в GLB уезжает трек на каждую кость
  каждого клипа, и кит толстеет вдвое ни на что.

Ретаргет Mixamo остаётся открытой дорогой: имена костей humanoid для этого и
сохранены. IK под рабочий цикл не понадобился — раструб сидит в сокете ладони,
и достаточно вести руку.

Геометрия здесь — не финальная модель, а корректная болванка: её задача —
скелет, bind-поза и контракт имён, чтобы код шага 6 писался и проверялся уже
сейчас. Ручной моделинг кота по концепту заменяет `build_body` и `build_head`,
не трогая ни скелет, ни сокеты, ни имена.

## Скелет

Кости humanoid названы по Mixamo (`mixamorig:Hips`, `mixamorig:Head`, …) — иначе
готовые клипы локомоции не ретаргетятся без правки имён. Сверх humanoid:

- `tail_1..3`, `ear_l`, `ear_r` — своя цепочка. В humanoid-ригах их нет,
  Mixamo не даст ничего: пружина в Blender или синус с отставанием в коде.
- `socket_hand_r`, `socket_back` — сокеты. Пропс на сокете не требует
  риггинга вообще: ни весов, ни стыков, ни совпадающей bind-позы.

Оси в Blender: X вправо, **-Y вперёд** (куда смотрит кот), Z вверх. Экспорт
приводит это к glTF +Y вверх, и кот смотрит в +Z — как капсула в рендере.

## Кит окружения

`build-env-kit.py` → `public/models/env-kit.glb`. Две породы мешей.

**Обломки** `debris_bag`, `debris_barrel`, `debris_crate` — кучи в игре тают
по одному обломку, поэтому генерятся не кучи, а куски. Каждый — text→3D через
AssetHub (Tripo 3.1), исходники в `gen/tripo/debris/`; в ките — 300 тр. и
карта 256². Рендер инстансирует их по хешу от id кучи, пока кит не приехал —
коробки.

**Модули двора** строятся в том же скрипте из примитивов с фаской в один
сегмент: при плоской заливке без текстур фаска — единственное, чем читается
ребро. Начало координат — середина клетки на земле, у настенных пропсов —
точка касания стены. Текстур нет ни одной, материалы плоские, по палитре
`src/render/palette.ts`.

| Модуль | Что |
| --- | --- |
| `floor_slab`, `floor_patch`, `floor_grate` | плитка в клетку: чистая, с латкой асфальта, с водостоком |
| `wall_block`, `_b`, `_c`, `_grille`, `_plate` | панель стены в клетку, из них растёт блок; три положения тайла и две с деталью, по хешу клетки; стыки — тёмные фаски |
| `edge_wall`, `edge_corrugated`, `edge_gate`, `edge_door`, `edge_curb` | ограда в рост по дальним сторонам — бетон и гофролист участками, ворота с лампой, дверь; низкий парапет по ближним |
| `prop_dumpster` | контейнер с крышкой и колёсами |
| `prop_barrel`, `prop_crate`, `prop_cart`, `prop_pallet` | реквизит на полу; клетки заданы в `core/world.ts` и заняты для симуляции, группу в клетке собирает рендер |
| `prop_lamp_wall` | настенный светильник, светящаяся пластина снизу; сам свет — точечный источник в рендере |
| `prop_vent`, `prop_ac` | вентиляция и кондиционер на крыши блоков |
| `prop_pipe`, `prop_pipe_joint` | труба в метр вдоль +X и шар-колено |

| `street_tile` | метр улицы: в ките ради материала асфальта, рендер тянет её до горизонта |

Расстановка пропсов — в рендере, по хешу блока стен; в симуляции их нет.

**Тайлы поверхностей** — `gen/textures/`: бетон пола, панель стены, асфальт.
Генерятся локально в ComfyUI (SDXL base) скриптом `gen/textures/gen-textures.py`
с нодой `seamless_tiling` (циклическое дополнение свёрток — картинка
замыкается сама на себя), ужимаются до 256², обесцвечиваются и тонируются в
цвет палитры так, что средний цвет остаётся палитровым. В GLB идут JPEG,
~15 КБ штука. В тайле не должно быть швов и трещин: шов между плитками —
фаска модуля, а рисунок размером в метр повторялся бы на весь двор.

## Известная мина

У автоматических ригов (Meshy) плывут веса таза, из-за чего ноги скользят при
ретаргете. Проверять на ходьбе сразу, до того как вокруг модели построено
полгода работы.
