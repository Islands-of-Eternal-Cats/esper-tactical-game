# NINE LIVES CORP — срез «Ржавый»

Первый играбельный прототип ядра. Один кот убирает двор сам; игрок кликает по
земле и говорит, где важнее.

Дизайн среза — [docs/prototype-plan.md](docs/prototype-plan.md).
Инженерные решения — [docs/tech-plan.md](docs/tech-plan.md).
Игра целиком — [docs/pitch.md](docs/pitch.md).

Поверх того же ядра — срез «Перестрелка»: два на два, игрок раздаёт приказы
сверху. План — [docs/tactics-plan.md](docs/tactics-plan.md); ссылка на бой —
`…/#31337/skirmish`, переключатель «срез» в панели.

## Запуск

```
npm install
npm run dev      # http://localhost:5173
npm run check    # линтер + типы + тесты
npm run build    # сборка и проверка бюджета загрузки
```

Управление: клик по земле — где важнее · правая кнопка — снять приоритет ·
колесо — зум · тянуть — панорама · пробел — пауза и обратно на прежнюю
скорость · 1 и 2 — скорости.

Двор целиком определяется сидом: стены и старт кота — константы, в тике
случайности нет вообще. Сид виден в интерфейсе, вводится руками и стоит в
адресе страницы, поэтому двор, на котором что-то пошло не так, отдаётся
ссылкой вида `…/#31337` — это и есть рабочая единица плейтеста.

## Что сделано

Шаги 1–5 порядка реализации из техплана.

| Шаг | Что | Где |
| --- | --- | --- |
| 1 | протокол, ГПСЧ, сетка и A\* | `src/shared/protocol.ts`, `src/core/{rng,grid}.ts` |
| 2 | симуляция и резервирование | `src/core/{sim,jobs,world,state}.ts` |
| 3 | воркер, цикл, команды, снапшоты | `src/worker/sim.worker.ts` |
| 4 | сцена на примитивах, камера, интерполяция | `src/render/` |
| 5 | клик → зона приоритета, строка состояния | `src/render/scene.ts`, `src/ui/hud.ts` |

Шаги 6–7 — модель Ржавого, анимации, кит окружения — ждут ассетов из Blender.

## Автоматические проверки

Все четыре из техплана на месте, `npm run check` и `npm run build`:

- **детерминизм** — один сид, разный размер пачки тиков (это и есть ×1 против
  ×3), одинаковый хеш состояния;
- **сохранение** — загрузка не позволяет перебросить зафиксированный исход;
- **границы модулей** — правило линтера на запрещённые импорты;
- **бюджет загрузки** — порог проверяется при сборке.

Отдельно `tests/behaviour.test.ts` держит те правила, ради которых срез
существует: кот не бросает почти доубранную кучу по клику, полный пылесос
опустошается раньше нового приоритета, пустая зона исчерпывается осмотром.

## Срез «Перестрелка»

Все семь шагов из [docs/tactics-plan.md](docs/tactics-plan.md).

| Шаг | Что | Где |
| --- | --- | --- |
| 1 | движение по сетке вынесено, общее для кота и юнита | `src/core/mover.ts` |
| 2 | линия видимости, укрытие, шанс попадания | `src/core/{los,combat}.ts`, `tests/los.test.ts` |
| 3 | автомат юнита, раскладка, режим в `Sim` | `src/core/{units,skirmish}.ts`, `tests/skirmish.test.ts` |
| 4 | протокол, капсулы, трассеры по событиям | `src/shared/protocol.ts`, `src/render/{units,glide}.ts` |
| 5 | выделение, приказ `move`, маркеры, HUD | `src/render/{select,scene}.ts`, `src/ui/hud.ts` |
| 6 | поиск укрытия, `cover` в снапшоте, щиток | `src/core/units.ts`, `src/render/units.ts` |
| 7 | кит юнитов из Mixamo: кот, риггнутый авториггером Mixamo, за своих, Y Bot за противника — у каждого свой скелет и свои клипы, переноса нет | `assets/export-for-mixamo.py`, `assets/build-unit-kit.py`, `public/models/unit-kit.glb`, `tests/unit-kit.test.ts` |

Оружие — несколько типов, характеристики в `src/core/weapons.yaml` (дальность,
темп, шанс, урон); `src/core/weapons.ts` проверяет форму при загрузке, кто чем
вооружён — в раскладке `skirmish.ts`. YAML собирается в объект плагином в
`vite.config.ts`, тесты — `tests/weapons.test.ts`.

Кот в перестрелке — не скелет из `rusty.blend`, а тот же меш, риггнутый в
Mixamo: `assets/export-for-mixamo.py` готовит его для загрузки, авториггер
строит скелет по мешу, клипы качаются уже для него — и ложатся без переноса.
Хвост авториггер не знает: его кости и веса — из эталона. Дворовые клипы
кота («Ржавый») по-прежнему на его собственном скелете.

Модели оружия — модульные, из набора Quaternius «Sci-Fi Modular Gun Pack»
(CC0, в репозитории не лежит): `assets/build-gun-kit.py` берёт из него части
по списку, снимает гнёзда корпусов и собирает `public/models/gun-kit.glb`
(`npm run assets:guns`, превью сборок — в `assets/guns/preview/`). Что из чего
собрано — `look` в `weapons.yaml`: корпус и части по гнёздам (`barrel`, `stock`,
`grip`, `magazine`, `top` — под прицел); рендер (`src/render/guns.ts`) ставит
их и вешает на ладонь так же, как раньше брусок. Кит грузится вместе с китом
юнитов, при первом входе в перестрелку; без него оружие — брусок. Контракт —
`tests/gun-kit.test.ts`.

Управление: клик по своему — выделить · тянуть — рамка · Shift — добавить ·
клик по земле — идти туда · правая кнопка — снять выделение · тянуть правой —
панорама.

Проверки: детерминизм на `skirmish` (×1 против ×3, приказы в одном тике,
сохранение посреди боя), завершаемость от десяти сидов, разнообразие исходов,
влияние приказа на исход.
