# План среза «Перестрелка»

Вертикальный срез тактики с отрядами поверх ядра «Ржавого». Вопрос, на который отвечает: **тянет ли это ядро бой в духе Call to Arms / Men of War** — юниты сами ходят, стреляют и прячутся, игрок раздаёт приказы сверху.

Срез не заменяет «Ржавого» и не трогает его код разрушительно: ядро расширяется, а не переписывается. Всё, что здесь появляется, живёт в тех же `core` / `render` / `ui` и под теми же правилами техплана — детерминизм, воркер, единственный словарь в `shared/protocol.ts`.

## Что должно получиться

Двор 20×20 с теми же стенами и пропсами. Два юнита игрока слева, два юнита противника справа, между ними стена с проёмом. Игрок рамкой выделяет своих, кликом по земле шлёт их вперёд. Юниты идут, видят врага, останавливаются, стреляют; попавшие под огонь ищут укрытие за ближайшей стеной. Кто-то умирает. Бой заканчивается за 30–60 секунд.

Готово, когда десять боёв от разных сидов проходят по-разному, но от одного сида — одинаково на любой скорости, и в каждом из них есть хотя бы один момент, где решение игрока «куда послать» было видно на исходе.

Чего в срезе **нет** и что не надо тянуть: техника, прямое управление юнитом, гранаты, инвентарь, мораль, несколько типов оружия, звук. Каждое из этого — отдельный шаг после ответа на главный вопрос.

## Что переиспользуется как есть

| Есть | Куда идёт |
| --- | --- |
| `Grid`, A\*, октильная метрика | движение юнитов и линия видимости — по той же сетке |
| `Sim.tick()` без времени, `fixed.ts` | таймеры перезарядки, наведения, поиска укрытия — всё в тиках и тысячных |
| `Rng` с сидом | разброс попаданий — единственная случайность боя, воспроизводимая |
| `cell / prev / next / route / progress / stepMs` | движение юнита рисуется ровно как кот, ни строчки нового кода интерполяции |
| воркер, `MAX_STEPS`, снапшоты | без изменений |
| `Zone` и `setZone` | остаётся как «зона внимания» для «Ржавого»; в тактике не используется |
| камера, зум, панорама, палитра, `env-kit.glb`, инстансинг | без изменений; сцена та же |
| тест детерминизма, бюджет сборки, правило импортов | те же проверки, бой в них просто попадает |

`Cat` не становится юнитом. Юнит — новая сущность `Unit` рядом; общее между ними — только движение по сетке, и оно выносится в `core/mover.ts`. Пытаться натянуть тактику на `CatMode` — самый быстрый способ сломать «Ржавого».

## Модель боя

Всё дискретное, всё в клетках и тиках. Никаких векторов и градусов в `core`.

**Видимость.** Линия между центрами клеток по Брезенхему; стена или пропс на пути закрывают её. Предвычислять не нужно: 4 юнита × 4 цели × 20 тиков в секунду — копейки. Дальность видимости и дальность огня — константы в клетках.

**Укрытие** — свойство клетки относительно направления. Клетка укрыта с направления `d`, если соседняя клетка в сторону `d` — стена или пропс. Юнит в укрытии от стрелка получает штраф к вероятности попадания. Это одна функция над `Grid`, без отдельной карты укрытий. «Полу-укрытие» пропсов от «полного» стен — второй шаг, не первый.

**Выстрел.** Раз в `RELOAD_MS` стрелок бросает ГПСЧ против шанса попадания: базовый × дальность × укрытие. Попадание — минус фиксированный урон, юнит с нулём здоровья умирает и становится трупом-клеткой (проходимой). Трассер и результат уходят в снапшот событием, не состоянием — рендер их проигрывает и забывает.

**Поведение юнита** — конечный автомат поверх `mover`:

```
idle ──видит цель──▶ aim ──ждёт AIM_MS──▶ fire ──▶ aim …
  │                    ▲
  │ приказ move        │ под огнём и не в укрытии
  ▼                    │
move ──пришёл──▶ idle  └── seek-cover ──▶ move (к клетке укрытия) ──▶ idle
```

Приказ игрока ставит `move` и очищает цель; юнит, дошедший до места, снова ищет цели сам. «Под огнём» — в него стреляли за последние `UNDER_FIRE_MS`. Укрытие ищется в радиусе `COVER_RADIUS` — ближайшая клетка, укрытая от последнего стрелка, с доступным путём. Не нашёл — стоит и стреляет.

Противник — те же юниты с тем же автоматом плюс один приказ на старте: «идти к точке». Отдельный ИИ командира срезу не нужен.

**Порядок обхода** — юниты по `id`, как и всё в `core`. Два юнита, стреляющие друг в друга в один тик, разрешаются порядком `id`, и это нормально: результат воспроизводим, а игроку такая асимметрия не видна.

## Контракт

Расширение `shared/protocol.ts`. Существующие типы не меняются.

```ts
// главный поток → воркер
type Command =
  | …существующие
  | { t: 'move';  units: string[]; cell: Cell }
  | { t: 'halt';  units: string[] }
  | { t: 'setMode'; mode: 'yard' | 'skirmish' }   // выбор среза при reset

// воркер → главный поток
interface UnitView {
  id: string
  side: 'player' | 'enemy'
  cell: Cell
  prev: Cell | null
  next: Cell | null
  route: Cell[]
  progress: number
  stepMs: number
  facing: Dir            // куда идёт или куда целится
  action: 'idle' | 'move' | 'aim' | 'fire' | 'dead'
  hp: number
  cover: boolean         // укрыт от своей текущей угрозы
  target: string | null
  status: string         // «прижат огнём», «ищет укрытие», «перезарядка»
}

/** Событие тика: рендер проигрывает и забывает. В состоянии не хранится. */
type Event =
  | { t: 'shot'; from: string; to: string; hit: boolean }
  | { t: 'died'; unit: string }

interface Snapshot {
  …существующее
  units:  UnitView[]
  events: Event[]
}
```

Поля движения намеренно те же, что у `CatView`, вплоть до имён: `render/path.ts` и интерполяция подключаются к юниту без изменений. `action` — единственный источник анимации, как и у кота. `status` — та же дисциплина «одна строка, почему он делает то, что делает»; для тактики это ещё важнее, потому что юнит, который «просто стоит», раздражает, а «прижат огнём» — объясняет.

События, а не состояние: выстрел живёт один тик. Если бы он лежал в состоянии, снапшот, пропущенный из-за `MAX_STEPS`, терял бы трассеры, а тест детерминизма сравнивал бы мусор.

## Структура

```
src/core/
  mover.ts       движение по сетке; вынесено из sim.ts, общее для кота и юнита
  los.ts         линия видимости, укрытие клетки
  combat.ts      выстрел, шанс, урон
  units.ts       автомат юнита, поиск укрытия
  skirmish.ts    раскладка среза: стороны, стартовые клетки, стартовые приказы
  sim.ts         вызывает тик юнитов рядом с тиком котов
src/render/
  units.ts       капсулы, потом кит; трассеры по событиям
  select.ts      рамка, подсветка выделения, маркер приказа
src/ui/
  hud.ts         режим, счётчик живых, статус выделенного
```

`Sim` получает режим: `yard` — кот и кучи, `skirmish` — юниты. Оба живут в одном классе, потому что тик, снапшот, сохранение и ГПСЧ у них общие; расходятся только наборы сущностей. Если через два шага окажется, что режимы ничего не делят, — разнести, но не заранее.

## Числа

В `core/tuning.ts`, отдельной секцией. Стартовая точка, не результат.

| | | |

| `UNIT_MS_PER_CELL` | 900 | вдвое быстрее кота: бой, а не уборка |
| `SIGHT_RANGE` | 10 клеток | пол-двора |
| `FIRE_RANGE` | 8 клеток | видит раньше, чем стреляет |
| `AIM_MS` | 800 | пауза перед первым выстрелом — читаемая |
| `RELOAD_MS` | 1200 | |

| `HIT_PER_CELL` | −0,04 | на восьми клетках 0,28 |

Шансы — в тысячных, как всё в `fixed.ts`; ГПСЧ даёт целое 0..999.

## Ввод

- Клик по своему юниту — выделить. Тянуть по земле — рамка, выделяет всех своих внутри. Shift — добавить.
- Клик по земле с выделением — `move`. Правая кнопка — снять выделение.
- Клик по земле без выделения — ничего. В `yard` клик по земле по-прежнему `setZone`.

Рамка живёт целиком в главном потоке: воркер знает только итоговый список `id`. Попадание в юнит проверяется по последнему снапшоту, по клетке — юнит занимает клетку, значит клик по клетке и есть клик по юниту.

## Рендер

- Юнит — капсула цвета стороны, до кита. Полоска здоровья над головой, три деления.
- Выделение — кольцо на земле. Приказ — маркер в клетке назначения, гаснет по приходу.
- Трассер — линия между клетками стрелка и цели на 3–4 кадра; попадание — вспышка на цели, промах — на клетке за ней. Всё по `events`, без состояния в рендере дольше одного проигрывания.
- Укрытие — маленький щиток у ног, когда `cover: true`. Игрок должен видеть, что юнит укрыт, иначе штраф к попаданию — невидимая механика.
- Труп — капсула лежит. Достаточно.

Кит юнитов — тот же пайплайн, что у кота: один скелет, `unit-kit.glb`, клипы `idle / run / aim / fire / die` из Mixamo, extras с `foot_speed`. Гуманоид — самый простой случай для ретаргета, проще кота. Но это шаг 7, и до него срез отвечает на свой вопрос на капсулах.

## Порядок реализации

| Шаг | Что | Готово, когда |
| --- | --- | --- |
| 1 | `mover.ts` вынесен из `sim.ts` | «Ржавый» работает как раньше, тесты зелёные |
| 2 | `los.ts`, `combat.ts` с тестами | видимость через проём и мимо стены, укрытие по направлению — в тестах |
| 3 | `units.ts`, `skirmish.ts`, режим в `Sim` | два на два стреляются в консоль от старта до конца, тест детерминизма зелёный на ×1 и ×3 |
| 4 | протокол, `render/units.ts`, капсулы, трассеры | бой виден, движение плавное |
| 5 | выделение, `move`, маркеры, HUD | игрок командует и видит, почему юнит делает то, что делает |
| 6 | поиск укрытия, `cover` в снапшоте, щиток | юниты сами прячутся, и это видно |
| 7 | `unit-kit.glb`, анимации | капсулы заменены |

Шаги 1–3 — технический ответ: живёт ли бой в этом ядре. Шаги 4–6 — дизайнерский: интересно ли командовать. Шаг 7 — когда ответы «да».

Оценка — две недели на 1–6 при работе вечерами. Шаг 7 зависит от ассетов, не от кода.

## Проверки

К существующим добавляются:

- **Видимость и укрытие** — таблица случаев на маленькой сетке: через проём, за углом, диагональ вдоль стены.
- **Детерминизм боя** — тот же тест, что для двора, на режиме `skirmish`; он должен упасть первым, если в бой попадёт float или `Math.random`.
- **Завершаемость** — от любого сида бой заканчивается не позже `N` тиков: никто не застрял в `seek-cover` навсегда.

## Что станет ясно и что решать потом

Срез ответит, держит ли ядро бой и читается ли он сверху. Он не ответит на три вещи, и их не надо решать сейчас:

- **Масштаб.** Десять юнитов на сторону — та же архитектура. Сто — линия видимости всё ещё дёшева, но поиск укрытия и A\* на каждый приказ надо будет ограничивать бюджетом на тик.
- **Техника.** Занимает несколько клеток и поворачивается — `mover` придётся обобщить. Не раньше, чем пехота станет интересной.
- **Сеть.** Lockstep на этом ядре — естественный путь, и детерминизм для него уже есть; но это отдельный срез со своими вопросами.
